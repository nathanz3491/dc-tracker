# 我们做了什么

针对那份 review 的两点：**公司维度视角**做完了，**数据源拓展**做了一半，政府数据试了四条路都不通。

数据截至 2026-08-02：221 个项目，96,532 MW，32 个州。

---

## 1. 公司维度 —— 完成

`tracker capex`，或控制台的 **Capex** 页。

数据库按**站点**存，这一页按**买方**看。Meta 自建园区，OpenAI 大多租 Crusoe 这类开发商的 —— 楼上挂谁的名字，和谁掏钱买算力，经常不是一回事。

难点是判断谁掏钱：`customer` 字段只有十分之一的行填了。所以按三条规则依次判断：源头点名的租户 → 运营商自建自用（标 `*`）→ 都不是就明确记成「没人具名」。最后 40% 能归属，剩下 60% 摆在明面上，而不是悄悄丢掉。

```bash
tracker capex                  # 按年
tracker capex --by-quarter     # 按季度
```

能回答：每家买方规划/已建多少 MW、投资、哪年哪季度落地、多少产能卡在障碍后面、几个项目已延期、最严重的障碍是什么。

**没做**：和公司自己披露的 capex 打通。那要另写一个读现金流量表的抽取器。

## 2. 数据源 —— 一半

| 要的 | 状态 |
|---|---|
| 电力公司 | **已接，未跑**。SEC 路径加了 14 家公用事业 |
| 建筑公司 | **已接，未跑**。6 家 E&C |
| 政府（审批、土建） | **试了四条路，一条没上** |

`seed/edgar-companies.toml` 从 20 家扩到 40 家。公用事业按**实测暴露**挑：每家覆盖的州至少占已跟踪产能的 1%（TX 34%、CO 12%、NM 9%、OH 8%、GA 8%、VA 8%）。给没有项目的州订一家电力公司，只是订噪音。

每一类用**自己的检索词**。公用事业不写 "build-to-suit"，写 "large load"、"interconnection agreement"。加了一类报告主体却不加它的词汇，就是新数据源回来空空如也、看着像「没东西」的原因。

```bash
tracker ingest edgar --kind utility --per-company 1   # 约 17 次 LLM 调用
```

实测：找到 19 份文件，准备好 17 份。**还没抽取**，所以今天库里的数据源构成和之前一样。

### 政府数据：四条路，四次失败

详见 [government-sources.md](government-sources.md)，`python scripts/probe_government_sources.py` 可复现。

| 路 | 为什么不通 |
|---|---|
| 市政开放数据（Socrata） | Loudoun、Prince William、整个弗吉尼亚和亚利桑那，一个数据集都没有。能查到的命中是 50 万美元的机房水泵改造 |
| FERC + 各州 PUC | 内容对，但全是 ASP.NET 表单，没有 API |
| 县政府新闻 RSS | 用本项目自己的过滤器打分：**177 条里 0 条**。Stargate 就建在 Abilene，Abilene 市政新闻只字未提 |
| Legistar 议程 API | 数据中心所在的县根本不是它的客户；查到的是 2005 年的市政 IT 采购 |

一条都没上，理由是：一个产不出东西、却让数据源构成看起来「有政府来源」的类别，比诚实的空白更糟。

有两件事今天就能用。公用事业的大负荷和并网承诺是**报给 SEC 的** —— 那就是政府强制披露，就是上面那条 `--kind utility`，还没跑。单篇政府文件本来也能读：`tracker ingest crawl --url <.gov 链接>`，会自动记成 `government_doc`。缺的是**批量发现**。

## 新命令

| 命令 | 干什么 | 花钱 |
|---|---|---|
| `tracker capex` | 按买方看产能和投资 | 免费 |
| `tracker duplicates` | 找重复行 | 免费 |
| `tracker merge --into ID a b c` | 合并成一行 | 免费，**会删行** |
| `tracker logic check` | 找互相矛盾的字段 | 免费，除非加 `--read` |
| `tracker logic resolve` | 把偏离自身来源的行改回去 | 免费，**会写库** |
| `tracker ingest edgar` | 读 SEC 文件 | 每份 1 次调用 |
| `tracker serve` / `cloudflare` | 网页控制台 / 发布到公网 | 免费 |

`tracker logic check` 是新的：别的检查问「这个值有没有出处」，它问「这些有出处的值互相对得上吗」。现在能找出 **21 处不可能**和 125 处可疑 —— 已通电却还标在建、规划 32 MW 却建了 100 MW、预计上线日期过去 944 天还标在建。

它还列出 **183 处两个来源打架的字段**，并说明库里为什么留了现在这个值。理由不总是「来源更可信」：`mw_built` 取最大（已通电容量只会涨）、`first_announced` 取最早、`phase` 取最靠后（除非有人说停了）、`name`/`company` 一旦写入就不再改。

## 修了一个一直在丢数据的 bug

`enrich` 日志里那行 `evidence quote ... is not in the article; ignoring`，丢的大多不是编的数，是真数。

拿 8 篇缓存文章里的 131 条引文实测：33 条没通过「原文必须一字不差包含」这一关，主因不是幻觉，而是模型**边引边把代词换成专名** —— 原文写「The campus is a single building ... 16.5 MW」，模型写「The **Austin** campus is ...」。改一个词，整条证据作废，容量就没了。

现在改成：包含不上时，取引文里**确实出现在原文中的最长一段**，并且**存原文的原话，不存模型改过的版本**，再补齐到句子边界（有一条正好断在 `...was $` 上，钱数被截掉了）。门槛 40 字符 + 至少占引文一半，拿「同一条引文去比对不相干的文章」做对照组调出来的，一条都没误判。

**通过率 75% → 95%，误判 0。** 防造假这条线没松：`_stated_in` 是拿**存下来的原文**去核的，值仍然必须有人真写过。风险条目走同一条路。

## 控制台：不用记命令了

**流程（Routines）** —— 命令页最上面，四条按顺序排好的常用流程，一次点击当一个任务跑，一条日志、一条历史记录：

| 流程 | 步骤 |
|---|---|
| 追新闻 | `sync` → `ingest geo` → `logic check` |
| 深挖已有的 | `enrich` → `ingest geo` → `gaps` |
| 整理数据库 | `duplicates` → `logic check` → `stats` |
| 出报告 | `stats` → `capex` → `verify` |

顺序是有理由的，页面上也写着：地理位置是免费查表，放在读文章**之后**才能把刚进来的行也定位上；矛盾来自新值，所以检查放最后。中间哪步真失败就停（`duplicates` 查出重复会返回非零，那是结论不是故障，继续跑）。

**表单也重做了**：字段是中文式的人话标签 + 真实 flag 并排，项目 id 改成**下拉选真实项目**（不用再开一个窗口去查 id），数字给默认值附近的几个档位，`sync` 那 13 个参数默认只露 3 个。

**确认分两种**：花钱的（可恢复 —— 钱可以明天再花）改成点第二下确认；`merge` 这种**删了没法撤**的，仍然要手打命令名。

**每个项目详情页有一段 AI 概览**（做成搜索引擎那种 AI overview 的样子），就是 Stats 页里的一张普通卡片，跟着一起滚动、排在数字下面：打开就自动生成、逐字流式输出，一句话 + 两三条要点，markdown 渲染，超过就折叠。圆角和阴影和别的卡片一模一样 —— 区分它的是底色，不是形状。按内容缓存 —— 同一行只花一次钱，再打开是免费的。它是对数据的**解读**，不是数据：不入库、不算来源、不影响置信度。

换成了 `M2-her`：**出第一个字 46.6 秒 → 2.7 秒，231 字 → 约 65 字**。

模型是**实测选的**，结果和模型列表给人的印象相反。按「第一个**可见**字」计时（`<think>` 里的 token 读者看不见，所以秒出 token 然后想二十秒的模型不叫快）：

| 模型 | 思考 | 第一个可见字 |
|---|---|---|
| MiniMax-M3（原默认） | 有 | 46.6s，**而且什么都没输出** |
| MiniMax-M2.7-highspeed | 有 | 15.5s |
| MiniMax-M2.1-highspeed | 有 | 12.5s |
| MiniMax-M2 | 有 | 12.4s |
| **M2-her** | **无** | **2.7s** |

注意普通 M2 比所有 `-highspeed` 都快。highspeed 快的是**每秒输出 token 数**，而这个活是「先固定思考一大段，再吐 70 个字」—— 吞吐量恰恰是最不重要的那个指标。M3 不只是慢：它把整个 token 预算全花在思考上，最后**一个字都没输出**。只有**去掉思考**才真正改变这个数字。

**`M2-her` 是唯一不思考的模型，所以现在是默认**：出第一个字 2.7 秒（对比 12.4 秒），平均 65 字，没有杂音漏出来。为此做了三件事，对所有模型都有好处：

- 提示词要求结尾写 `[[END]]` —— API 自带的 `stop` 参数收下了但**不生效**，靠不住；
- `overview.RUNAWAY` 在**流**上就地截断（在 `[[END]]` 或模型开始写第二遍的地方）。截流而不是截文本才省时间：放弃 generator 就会关掉连接，答案之后的 token 根本不用等。不管的话 M2-her 会写 756–982 字、用「Final answer (last round)」重复好几遍、还会报自己的字数；
- `MODEL_TOKEN_CAP` 把 token 预算压到它能接受的 2048。不压的话每次请求都是 HTTP 400，这个模型根本选不了。

**这个默认是有代价的，而且代价是实测出来的。** 格式从来不是真问题：有一行 construction 轨道写着 `nothing reached`、其余四条都过了，它写成「All tracks complete; construction the last to finish」，把整行里最有信息量的字段读反了。它还编过数据里根本没有的电力公司和审批流程，以及「Major capex is confirmed via gas」这种没有意义的句子。同一行 `MiniMax-M2` 读对了。这个行为**不稳定**：同一行后来连跑四次都是干净的。

这笔交易的边界，就是这个面板本来的设计：它明确标着「模型写的」、不入库、不算来源、不影响置信度 —— 所以写错了是**旁边带引用的正确数值旁的一个错误看法**，而不是一个错误的数值。想换回准确度，`TRACKER_MINIMAX_FAST_MODEL=MiniMax-M2`，代价是每行多等约 10 秒。

其余模型的思考链**关不掉** —— `thinking`、`reasoning_effort`、`enable_thinking` API 都收下但都不生效，assistant 预填 `</think>` 也没用；把提示词缩短 1300 字符同样没用，思考是固定开销。思考内容在流式过程中就被过滤掉，不会出现在页面上。

提示词里加了一条给快模型的规矩：**五条轨道一行一行读，只有那一行写着 `nothing reached` 才算卡住**。不加这条，它会把两条轨道并成一句话说 —— 「审批和电力都没进展」，而审批那行明明写着 `permit_filed, permit_approved`。这是对着屏幕上的数据说假话，是这个面板最不能犯的错。实测 8 个项目：**加规矩前 2 个读错，加完 0 个**。

**`tracker point --url <链接>`**：手上已经有链接（新闻稿、公告）就直接读，不用去搜。新老项目都行，走的是同一条写入路径，证据门槛和去重规则一样管用。

## 报数之前必须知道

- **只有 40% 的项目能说出买方是谁**，其余都在最后一行。
- **只有 35% 同时有容量和日期**，只有这些能进年份列。
- **17 个园区被存了不止一次**，24,125 MW 被重复计算。对公司维度打击最大：OpenAI 虚高 **53%**，Oracle 虚高 100%。
- **投资那一列最不可信**：混着没核实的数字，通常是整个计划的总额（「OpenAI 的 5000 亿 Stargate」）挂到了单个站点上。先看兆瓦。
- **34% 有日期的项目落在 1 月 1 日**，因为「2027 年某个时候」就归一化成那天。季度视图看趋势，不看排期。
- **所有数字都是下限**。没人报过容量的项目按 0 算。

这些控制台都直接印在页面上，不用记。

## 先做这三件事

1. **合并重复行。** 控制台 → Capex → 「One campus, several rows」。勾选保留哪一行，输入 `merge`。点几分钟，这是公司维度表对与错的分界。选哪一行不影响数值 —— 合并后每个字段都按合并后的全部来源重算。
2. **设 SEC 的 User-Agent。** `.env` 里加 `TRACKER_USER_AGENT=dc-tracker/0.1 (+contact: you@example.com)`。用自带占位符会被直接封。
3. **跑公用事业文件。** `tracker ingest edgar --kind utility --per-company 1`，约 17 次调用，把「电力数据源」从一句话变成能指着看的行。
