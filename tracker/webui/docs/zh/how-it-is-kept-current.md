# 数据如何保持更新

追踪系统每天傍晚（北京时间）自动更新一次，8:00 的晨报邮件会报告这次更新带来了什么。本页说明更新做了哪些事，让你知道“最新”指的是什么。

## 每晚更新

更新按轮次进行，当某一轮不再带来任何改进时就停止。每一轮：

1. **免费重新处理已有的数据。** 根据来源重新计算各字段，用明确写出日期的文章补全日期，并执行安全的修复。
2. **处理不可能成立的数字**——例如两种单位被混淆，或把整体计划的总数存成了单个场地的数字。
3. **重新核查障碍**：对那些报告时没有附带原句的障碍，拿文章重新核对。
4. **解决来源之间的矛盾**，排除那个实际上说的是别的事物的数字。
5. **处理疑似重复项目**——把不同的场地区分开；只有在模型高度确信、且没有触发任何安全限制时，才会合并一对记录。参见[重复项目](duplicates)。
6. **为信息不完整的园区补缺**：搜索并阅读更多关于它们的文章，并针对仍缺失的字段提出定向问题。
7. **重新阅读较早的文章**——那些在读取规则最近一次收紧之前读过的文章——让旧记录也符合今天的核查标准。
8. **发现新文章**，新闻优先，并阅读它们——新园区就是从这里来的。

在合并或删除任何内容之前，都会先保存一份数据库副本；当晚改动过的每一个数值都会被列出，附上它现在所依据的原句，供人工复核。

## 什么时候更新什么

| 内容 | 时间 |
| --- | --- |
| 发现并阅读新文章 | 每天傍晚 |
| 为信息不完整的园区补缺 | 每天傍晚，每次几十个园区 |
| 重新阅读已引用的文章以发现变化 | 每篇文章每隔几周一次 |
| 重新检查屏蔽追踪系统的发布方 | 每周 |
| 晨报邮件 | 北京时间 8:00 |
| [Updates](updates)（动态）页面 | 傍晚更新一存入新内容就立即更新 |

Updates 页面上的 **last crawl**（上次抓取）显示最近一次抓取新文章的时间；如果距今已超过两天，它会变成琥珀色。

## 它不会做什么

- **没有来源，它不会改动任何数值。** 每一次改动都依据文章中的一句原句，或依据一条连同理由一起记录的决定。
- **它不会删除证据。** 被排除的数字仍然可见，作为一条已被搁置的说法。
- **它不会猜测。** 没有任何公开信息的字段保持为空——参见[为什么字段为空](empty-fields)。

## 为什么某个数字变了

如果某个园区的数字在一夜之间变了，请打开[项目详情页](project-page)：

- 字段上的 **N other claims**（N 条其他说法）显示各来源给出过的每一个数值，以及现在保留的是哪一个；
- 备注记录了针对它做出的任何决定——某个数字被排除、某个矛盾被解决、某个重复项目被合并进来——并附有理由；
- **Citations**（引用）显示各个来源，包括最新抓取的来源。

常见原因是：出现了一篇新文章，某个数字因属于别的事物而被排除，或者两行记录被合并。
