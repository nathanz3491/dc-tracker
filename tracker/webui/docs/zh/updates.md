# 动态

**Updates**（动态）页面展示近期关于你所关注对象的报道。它是每天应该首先打开的页面，晨报邮件就是它的摘要。

它覆盖的范围由你在 [Monitor](monitor)（关注）页面上的关注列表决定。如果你还没有关注任何内容，页面会提示这一点，并给出指向那里的链接。

## 什么算一条动态

一条动态是某个来源对你所关注园区的报道：一个里程碑（购得土地、审批获准、破土动工、通电、首个客户）、一次延期、一次扩建，或一个障碍（当地反对、电网容量限制、诉讼、用水纠纷、融资困难）。

只显示**过去两个月内报道**的内容。"报道"指文章的发布日期；如果不知道发布日期，就用事件本身的日期；两者都没有时，用系统存入它的日期。

一条动态是好是坏，取决于事件的类型 —— 通电是好消息，延期是坏消息 —— 而不是模型的看法。

## 顶部的标签

关注列表中的每一项对应一个标签，显示：

- 该项的名称，以及它匹配到多少个项目（**Np**）；
- 时间窗口内的 **▼n** 条坏消息（红色）和 **▲n** 条好消息（绿色）；
- 如果系统中还没有任何内容与该项匹配，显示 **no match**（无匹配，琥珀色）。

点击一个标签，只显示该项的动态；**show all watches**（显示全部关注项）可取消筛选。**Edit the list on Monitor →**（在 Monitor 上编辑列表）会带你去关注列表。

## 四个统计块

| 统计块 | 统计内容 |
| --- | --- |
| **New since your last email**（自上封邮件以来的新动态） | 在你上一封晨报邮件之后进入系统的动态。在你收到第一封邮件之前，它显示为 **New in the last day**（过去一天的新动态）。 |
| **Needs attention**（需要关注） | 坏消息：障碍和延误。点击可把列表筛选为这些内容。 |
| **Good news**（好消息） | 好消息。点击可筛选。 |
| **Still open**（仍未解决） | 过去两个月内报道、至今仍未解决的障碍，以及它们涉及你的多少个项目。点击可前往 Monitor。 |

## 控件

- **week / month / 2 months**（一周 / 一个月 / 两个月）—— 列表往回追溯多久。默认是一周。
- **all / needs attention / good news / worth emailing**（全部 / 需要关注 / 好消息 / 值得发邮件）—— 显示哪些动态。*Worth emailing* 是一条动态进入晨报邮件必须达到的门槛。
- 右侧的 **last crawl**（上次抓取）—— 系统上一次抓取新文章的时间。如果距今超过 48 小时，它会变成琥珀色并显示已过去几天：此时新闻可能不是最新的。

## 列表

**New since your last email** 排在最前：即你上一封邮件之后到达的内容（如果你还没收到过邮件，则是过去 24 小时内的内容）。

接下来是 **Reported this week**（本周报道；或本月、过去两个月），按报道日期分组 —— *Today*（今天）、*Yesterday*（昨天），然后是具体日期 —— 每天都显示当天的动态数、坏消息数、好消息数和已发邮件数。

每条动态是一张卡片：

- 彩色边框和符号：绿色 **+** 表示好消息，红色 **−** 表示坏消息，灰色 **·** 表示中性；
- 标题，然后是 *公司 — 项目* 形式的园区名称，点击可打开[它的页面](project-page)；
- 适用时显示的标记：
  - **expected, not reached**（预期，尚未发生）—— 日期在未来，所以这是一个时间表，而不是已经发生的事；
  - **the blocker moved**（最大障碍有变）—— 该园区的最大障碍发生了变化；
  - **✓ emailed**（已发邮件）—— 它出现在你的某一封晨报邮件中；
  - **worth emailing**（值得发邮件）—— 它达到了邮件的门槛；
- 它改变了什么、详细内容，以及它所依据的原句；
- 报道时间、发生时间（或预计时间）、发布方，以及它匹配了你的哪一个关注项。**+N more reports**（另有 N 篇报道）表示还有其他文章说了同样的事。

**By company**（按公司）按关注项汇总该时间窗口：项目数、需要关注的数量、好消息、未解决的最大障碍，以及各项进展的现状（例如 *power: waiting on energized*（电力：等待通电））。点击一个名称，可把列表筛选为该项。

页面底部的 **Show N unconfirmed — nobody could quote them**（显示 N 条未确认动态 —— 无人能引证）会显示那些有报道、但无法用文章原句佐证的动态。它们以淡色显示，并且永远不会出现在邮件中。参见[数值从哪里来](provenance)。

## 最近被提到的新供应商

列表下方的 **Newly mentioned suppliers**（最近被提到的新供应商）列出在时间窗口内**首次**被来源点名出现在某个园区上的公司 —— 范围是**追踪的全部园区**，而不仅是你关注列表里的。它跟随 **week / month / 2 months**（周 / 月 / 两个月）控件。

- **每家公司一行**，无论有多少个园区提到它。公司名下逐个列出园区：该公司在那里的角色、园区名称（点击打开[它的页面](project-page)）及其运营方和地点、该公司在这个园区上首次被提到的日期，以及文章的发布方（↗ 打开原文）。
- **悬停或轻点公司名**（或某个园区），可看到提到它的那句原文。
- **Suppliers / Customers / Builders & owners / All**（供应商 / 客户 / 建设方与业主 / 全部）选择列出哪些角色，每项都带数量。*供应商*指承包商和电力公司，也是本栏默认打开的一项：每个新进入追踪的园区都会带来它自己的开发商、业主和运营方，那是关于园区本身的消息，而不是关于谁在为它供货。新被点名的*客户*就是新租户 —— 因此只需轻点一下即可切换查看。
- **campus new to the tracker**（新进入追踪的园区）表示该园区本身就是在时间窗口内首次被报道的：上面的每家公司之所以“新”，是因为园区是新的。没有这个标记的，是追踪中已有园区上出现的新名字。
- *首次被提到*指该园区的任何引用来源第一次点名这家公司的时间，按文章的发布日期计 —— 所以本周才找到的一篇旧文章，不会让一家老供应商变成“新”的。这与[项目页面](project-page)上 **new** 标记的规则相同。角色已经结束的公司（例如已离开的租户）不会列出。
- **Show N more … (待确认)**（再显示 N 家…… 待确认）会显示只在不支持其所标角色的句子中被提到的公司 —— 例如被归为承包商的一家银行。名字确实出现在文章里，但角色未经确认。在某一个园区上已确认的公司照常列出，它的其他园区标记为待确认。

默认显示最新的十二家；**Show all**（显示全部）列出其余。[公司页面](companies)对它自己的园区也有同样的一栏。

## 晨报邮件

每天 **北京时间 8:00**，系统会把你关注列表中新出现、且值得发邮件的内容发邮件给你，前提是这些内容之前没有发给过你。

- **有新闻的日子**，邮件主题会写出第一条动态，以及还有多少条。邮件逐条列出每条动态的发生时间、报道时间和发布方链接，然后是一份简短的 *watch for*（留意）清单，列出下一步可能推动你所关注项目的事项，最后是一个按钮，用于在 Updates 页面打开本周内容。
- **平静的日子**，邮件主题会说明没有新动态，以及你的项目中有多少仍有未解决的最大障碍；邮件会列出仍未解决的事项，以及什么能解决它们。

一条动态会进入邮件，需同时满足：之前没有发给过你；达到 *worth emailing* 门槛；在过去 60 天内报道；并且它是在你上一封邮件之后进入系统的，或者是在过去 14 天内报道的（两者满足其一即可）。

> [!IMPORTANT]
> 邮件没有退订链接。邮件跟随你的关注列表：**关注列表为空** 会停止发送，**watch everything**（关注全部）也会停止发送 —— 关注整个数据库时不发邮件，因为那等于把整个数据库发出去。两者都可以在 [Monitor](monitor) 上更改。

如果你错过了某封邮件，它本应包含的所有内容在本页面上保留两个月。

## 页面为空时

- *Nothing reported this week*（本周没有报道）—— 你列表上的对象在这个时间窗口内没有任何报道。可以扩大时间窗口、在 Monitor 上添加公司，或者去那里看看仍未解决的事项。
- *Nothing for X this week*（本周 X 没有动态）—— 你选中的标签没有新闻，但其他标签有。再次点击该标签即可查看全部内容。
- *Nothing matches this filter*（没有符合此筛选条件的内容）—— 选择 **all**（全部）。
