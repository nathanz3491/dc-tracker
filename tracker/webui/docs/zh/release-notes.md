# 更新说明

控制台读者会注意到的变化，最新的排在最前。控制台的版本号显示在其顶部栏中。

## 2026 年 10 月 21 日

### 项目详情页按阅读顺序重写

- **摘要在最前**：规划容量、运行容量、还有多少待交付及何时到期、预计上线日期、延期风险及其原因、投资及每兆瓦成本；然后是买方、运营商、电力、关注事项、最大障碍，以及这一行的来源有多充分。把鼠标移到数字上可看到背后的原句。参见[项目详情页](project-page)。
- **各部分按投资者的阅读顺序排列。** 进展与时间线、横向比较和引用默认收起；点击标题即可展开或收起，页面会记住你的选择。
- **十二个字段分两栏排列**，每个一行。原句悬停即可看到，展开某个字段可看到关于它的每一条说法。
- **障碍每个一行**，展开即可看到原句，已解决的障碍收起。分期列表先显示前十二个部分。
- **仍有容量待交付的在运行园区，按其推迟记录和障碍判断延期风险** —— 在它的详情页和所属公司的页面上都是如此 —— 不再因为部分已运行就算作低风险。

### 每个页面上的数字保持一致

- **运行容量永远不超过规划容量。** 两者矛盾时，由证据更充分的数字判断哪一个描述的是别的东西。Englewood 不再显示"规划 18 MW、运行 6,750 MW"：6,750 其实是被写成兆瓦的千瓦数，这样的数字现在会被剔除。参见[数字与日期](numbers-and-dates)。
- **分期面板的标题数字就是园区自身的运行容量**，与上方卡片上的数字相同。当园区的各分期描述的容量超过园区本身时，条形图下方会有一行说明。参见[项目详情页](project-page)。
- **每家公司在各处只用一个名称。** AWS、Amazon Web Services 和 Amazon 都显示为 *Amazon*；Facebook/Meta 显示为 *Meta*。园区详情页仍会在名称旁显示来源的写法。
- **公司的合计数字与 Capex 页面一致。** 被重复记录的园区只计一次，已取消的不计入，租户只计入自己的楼栋而不是整个园区。参见[公司页面](companies)。
- **来源点名了多个买方的园区，不计入其中任何一家**，直到有来源说明如何划分。Fermi America 在 Amarillo 的 11 GW 园区此前被计在 Amazon 名下。参见 [Capex](capex)。
- **发电站和太阳能电站不是园区。** 为在密西西比州给 AWS 供电而建的三座设施已被移除，新的同类设施也会被挡在外面。

### 延期

- **疑似延期。** 预计上线日期已过——以其所指的整个月份、季度或年份为准——却没有任何投运消息的园区会以琥珀色标出：在它的详情页上、[项目](projects)表格的 **Late**（逾期）列和 **Suspected delays only**（只看疑似延期）筛选中，以及它所属公司的页面上。参见[数字与日期](numbers-and-dates)。

### 公司页面

- **以兆瓦来看。** 卡片依次为规划、运行、在建，以及未来三年到期的容量。**Stage, in megawatts**（按兆瓦计的阶段）把规划数字按进展拆分。
- **供给与延期风险。** 新增的 **Supply**（供给）部分按年份显示未来三年的容量、每个园区所占份额及其延期风险——高、较高或低——并附上依据。占这部分供给五分之一或以上、又可能推迟的园区，会在条形图上方被点名。参见[公司页面](companies)。

### 项目详情页与项目表格

- **相关方改为名称列表**，按角色每行列出。把鼠标移到名称上可看到背后的原句；**new**（新）标记最近 30 天内才第一次被提到的公司。
- **字段以文字命名**，英文和中文并列——*Planned · MW、规划容量*——展开字段时显示存储名称。
- **项目表格适应窗口宽度**，向下滚动时列名保持可见。镇和州合并为一列 **Location**（地点），各列按阅读顺序排列。

## 2026 年 9 月–10 月

### 及时跟进新闻

- **为每个园区搜索新闻。** 追踪系统每晚查询自上次查看以来关于每个园区的报道，因此园区投入运营、开工或被取消，会在一两天内被发现，而不是等到有人恰好研究它时才发现。参见[数据如何保持更新](how-it-is-kept-current)。
- **每晚读取建设方自己的网站。** 建设方自己的数据中心网站上发布的任何新内容——例如 Meta 的“Hello, Tulsa!”和“Kuna, we are online!”——都会在第二天晚上被读取。这些网站很早以前就宣布、而追踪系统此前漏掉的园区，现在正在补入。

### 运行状态与地图

- **运行状态页。**[运行状态页]({{status}})显示控制台、API 和本文档能否访问，以及每晚更新的运行情况。该页面是公开的，无需登录即可查看。
- **新版地图。**[地图](map)显示全国和各州的合计数字，统计方式与资本支出页面相同；圆点大小按规划容量分档；可以隐藏某个阶段、放大到 10×，并在表格中查看每个州的数字。3D 视图以及按可信度和按运营商着色的功能已移除。

### API

- **只读 API。** 程序可以读取园区、园区的各项数字和来源、公司、按买方统计的资本支出，以及你关注列表中的新闻，只需使用在 Account（账户）页面创建的密钥。参见 [API 入门](api)。
- **按账户开关 API 权限。** 管理员可以在 Admin（管理）页面为每个人开启或关闭 API 权限。关闭后此人的密钥失效但不会被删除。未使用邀请码注册的账户默认关闭。

### 文档

- **本文档。** 控制台原来的 Help（帮助）页面已由本文档网站取代，提供英文和中文版本，并支持搜索。点击控制台顶部栏中的 **Help**（帮助）即可打开。

### 读懂数据

- **承诺在某个时段内完成的日期，不再在该时段开始时就被视为逾期。** “预计在 2026 年下半年”要到 2027 年才算延迟。在此之前，一些正确的预计日期被当作逾期清除了。
- **没有人能读取的排队文章会被丢弃，** 而不是一直等在队列末尾，因此队列反映的是真正可以读取的内容。
- **目录网站和维基只用于补缺。** 设施目录或维基不再压过第一手来源；只有在没有任何第一手来源说明某个字段时，它才会填补该字段。
- **只要存在覆盖整个园区的数字，单栋楼的数字就不再充当整个园区的数字。**
- **没有任何人公开的字段，在搜索过两次后即视为已作答，** 因此园区不再因为根本不存在的信息而被卡住。

### 页面

- **公司页面。** 每家公司都有一个页面，列出它的园区（它在哪里建设、在哪里是租户）以及它的近期新闻。控制台中各处的公司名称都链接到该页面。
- **每个园区都有一个引用页面，** 这样拥有几十个来源的园区依然清晰易读。
- **关注单个项目：** 在 Projects（项目）列表的每一行和每个项目详情页上都可以用 ☆ 关注。
- **Monitor**（关注）取代了 *Watch for*（关注事项）；关注列表在那里编辑。旧链接仍然可用。
- **地形图**以柱状显示，一眼就能看懂。

### 动态与邮件

- **邮件报道的是几天前的新闻，而不是几周前的，** 并注明每条消息的报道时间。
- **较晚才发现的旧文章不再作为新闻出现。** 文章按发布时间标注日期，而不是按追踪系统发现它的时间。
- **来自屏蔽自动读取的发布方的报道** 再次进入追踪系统——通过转载同一消息的其他媒体。
