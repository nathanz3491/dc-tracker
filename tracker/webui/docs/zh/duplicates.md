# 重复项目

同一个园区在新闻里常常有不同的叫法：一篇文章写开发商，另一篇写租户；一篇写镇名，另一篇写县名；一篇称它为“Project Blue”，另一篇用它的地址。如果追踪系统分辨不出两篇文章说的是同一个场地，就会为它建出两行记录。

重复项目并非无害。它会把一个园区的兆瓦数算两遍，记在其买方名下。

## 如何发现疑似重复项目

系统在同一个镇或县内比较各行记录；对于同一家公司、同一个州的记录，也会跨镇与县进行比较。当两行记录有某种共同点、提示它们是同一个场地时，就会被标记为一对疑似重复。按证据强弱排序：

- **名称相同**，且公司相同；
- **具名的楼栋或期相同**；
- 两行记录中**有同一家公司**以某种角色参与；
- 一行按**镇**归档，另一行按**县**归档；
- **名称有重叠**。

相互重叠的各对记录会按园区归成一组。

## 解决之前只计一次

在一组记录尚未解决时，[资本支出](capex)只计入其中**一行**——优先选有具名租户的那一行，其次选最大的，再次选最早的——其余各行则搁置在一旁，其兆瓦数显示为 *skipped*（已跳过）。没有任何数字被重复相加，这一步也不会自动合并任何记录。资本支出页面上的 **N campuses are stored more than once**（N 个园区被存储了不止一次）横幅会列出这些组。

## 一对记录如何解决

一对记录有两种解决方式：

- **已排除**——判定为两个不同的场地。这一对不再被标记，资本支出页面也不再因它而搁置任何一行。该决定会连同决定人一起记录在案。
- **已合并**——判定为同一个场地。所有来源、里程碑和障碍都移到其中一行，另一行被删除，每个字段都根据合并后的全部来源重新计算。保留哪一行由规则决定（来源最多者优先，其次是已填字段最多者，再次是编号最小者），而不是凭偏好。

合并由追踪系统的维护者执行，也由每晚更新在严格限制下执行：模型必须以高可信度判定这一对是同一个场地；如果唯一的证据只是名称中有一个相同的词、镇与县的对应，或者两行记录的位置相距很远，合并就会被拒绝。它无法解决的记录对会留给人工处理。

> [!WARNING]
> 合并无法撤销，被合并掉的那一行的编号也会失效。如果一个指向 `/projects/<number>` 的链接显示 *No project #N*（不存在项目 #N），这个园区很可能已被合并到另一行。

任何人都无法在控制台中合并或排除记录对；控制台只负责显示它们。

## 一个园区，多栋楼

同一园区的不同楼栋或不同期不算重复项目。它们是同一行记录下的**分期**，每个分期有自己的容量、状态和租户——参见[项目详情页](project-page)。追踪系统也会留意同一栋楼以不同名称被描述两次的情况（“Phase I”“first phase”“Building A”），并会报告出来，而不是把它的兆瓦数加两遍。
