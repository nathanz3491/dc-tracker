# 资本支出

**Capex**（资本支出）页面按**买方**汇总追踪数据。买方是真正使用这些容量的公司，往往不是建设方。例如，开发商为某家云计算公司建设的园区，会计入这家云计算公司名下。

暂停和已取消的园区不计入本页的任何数字。

> [!IMPORTANT]
> **这里的每个数字都是下限。** 没有任何来源说明过的容量按零计算，所以真实总量更高。兆瓦（MW）数比美元数更可信：容量的披露远比投资频繁，口径也更一致。

## 汇总卡片

| 卡片 | 含义 |
| --- | --- |
| **planned or building**（规划或在建） | 所有计入园区的规划容量，单位兆瓦（MW）。 |
| **already running**（已运行） | 目前已通电运行的兆瓦数。 |
| **confirmed spend**（已确认投资） | 有原句引证支持的投资。 |
| **claimed, not counted**（已披露、未计入） | 有报道但没有计入总数的投资，例如针对整体计划而非单个园区的数字。 |
| **have a named buyer**（有具名买方） | 买方已知的容量所占比例。 |

## 谁算作买方

对每个园区，按以下顺序判断：

1. 来源中被称为**客户**的公司；
2. **Buyer**（买方）字段（不同写法会合并为同一家，例如 Meta 和 Facebook、AWS 和 Amazon 算作一家）；
3. **运营商本身**，前提是它自己使用这些容量：大型云计算公司、GPU 云厂商，以及 AI 实验室等少数其他公司；
4. 否则归入 **(no named customer)**（无具名客户），无论规模大小，始终排在最后。

如果租户只被描述为"一家财富 100 强公司"或"一家领先的超大规模云厂商"，就无法追踪到具体买方，其容量会归入 *(no named customer)*。

如果一个园区按楼栋或分期拆给不同租户，每个租户只计入自己那几个分期的兆瓦数。投资不按这种方式拆分：拆分就意味着要凭空编造一个比例。

如果买方是根据园区的所有者推出来的，而不是来源直接点名的，会标一个星号（`*`）。

## 重复项目只计一次

当追踪系统怀疑同一个园区被存成了多行时（通常是因为不同文章对它的叫法不同），会出现横幅 **N campuses are stored more than once**（N 个园区被重复存储）。每组疑似重复只计**一次**；其余行被搁置，其兆瓦数显示为 *skipped*（已跳过），绝不会重复计入。

> [!NOTE]
> 把重复的行合并为一行由追踪系统的维护者完成，不在控制台中操作；本页上的任何操作都不会改动数据。参见[重复项目](duplicates)。

## 表格

| 列 | 含义 |
| --- | --- |
| **buyer**（买方） | 容量为谁而建。 |
| **sites**（园区数） | 园区数量。 |
| **planned**（规划） | 规划兆瓦数，并用条形图显示该买方所占份额。 |
| **running**（运行） | 已投运的兆瓦数。 |
| **confirmed $**（已确认投资） | 有原句引证的投资；灰色的 *+$X claimed*（另有 $X 已披露）表示有报道但未计入的投资。 |
| **MW arriving, by year**（按年投运兆瓦） | 每年（或每季度）预计上线的兆瓦数。 |
| **MW at risk**（风险兆瓦） | 存在未解决障碍的园区的兆瓦数。 |
| **delays**（延期） | 报道过延期的园区数量。 |
| **biggest obstacle**（最大障碍） | 最常见的严重障碍，例如 *Grid capacity · blocking*（电网容量 · 阻断）。 |

**pipeline by year / quarter**（按年 / 按季度显示项目储备）用于切换投运列。季度数据请看整体形态，不要当作时间表：很多来源只给出年份，只有年份的日期无法归入某个季度。因此，页面会显示有多少个有日期的园区落在 1 月 1 日。

标题上的小数字指向表格下方的编号注释，说明每一列如何计算、排除了什么。

## 深入查看

点击买方名称或该行中的任意数字，可展开其背后的园区；再点一次收起。明细列出每个园区及其贡献，以及**set aside as suspected duplicates**（作为疑似重复项目而搁置）、任何地方都不计入的行。点击某个园区可打开[它的详情页](project-page)。

鼠标悬停在买方名称上会弹出一张卡片，显示其基本情况：园区数、其中有多少是根据所有权归属推定的、被搁置的兆瓦数、已披露但从未确认的资金，以及一段由模型根据表格自身数据写的简短 **AI reading**（AI 解读）。和项目详情页上的 AI 面板一样，它不是证据，不会被保存，运行一次就要花钱。

## 表格下方

- **How much of the data this page covers**（本页覆盖了多少数据）：每项数字在多大比例的园区上有值。
- **N project(s) list a builder as the customer**（N 个项目把建设方列为客户）：被点名的租户实际上是施工或开发公司的行，这通常是来源的错误。
- **One campus, several rows**（一个园区，多行记录）：疑似重复项目的分组，以及每一对被提出的原因。
