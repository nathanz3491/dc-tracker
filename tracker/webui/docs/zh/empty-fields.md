# 为什么字段为空

空单元格并不总是缺口。它往往就是正确答案，追踪系统会区分不同情况。

## 因不适用而为空：不适用（n/a）

有些字段暂时不可能有值。处于已宣布、审批中或在建阶段的园区，其**运行容量**为 {{v:na|—}} *不适用（n/a）*：还没有任何设施通电，所以没有可报告的内容。这类空白比其他空白显示得更淡，表示"没什么可看的"，而不是"什么也没找到"。

## 因本来就没有而为空：通常是对的

- **买方。** 大型云计算公司自建园区时，没有外部客户。这类园区的买方为空是正确的。
- **最大障碍。** 为空表示没有报道过未解决的障碍。在任何时刻，大多数园区都没有。
- **县。** 横跨多个县的城市（如休斯敦、奥斯汀、堪萨斯城）不填县名，而不是填一个猜测的县。

## 因已搜索但未公开而为空

追踪系统会主动查找缺失的数字：它会搜索并阅读关于某个园区的更多文章。当一个字段**已搜索过两次且没有任何公开信息**时，系统就不再在它上面花费精力，并将其记录为 *published nowhere*（未见公开）。该字段保持为空，不会编造任何数字；一旦园区获得新来源，它就会自动重新打开。

这在私人开发商中很常见，他们往往从不公开容量或投资；对于没有人作出承诺的日期也是如此。

## 因唯一的数字被排除而为空

当一个字段背后唯一的数字被证明不适用于这个园区时，该字段可能会失去它的值：比如那是整体计划的数字、另一个园区的数字，或者园区早已超出的早期规划。追踪系统宁可什么都不显示，也不愿显示一个明知说的是别的东西的数字。[项目详情页](project-page)会在注释中显示这类决定，**N other claims**（另有 N 条说法）会显示被搁置的那个数字。

## 因尚未有人找到而为空

有时候，某个数字只是在追踪系统读过的任何内容中都还没有被报道。这些正是每晚更新要处理的对象，参见[数据如何保持更新](how-it-is-kept-current)。

## 不为空，但不是事实

有两种情况看起来已填写，但分量很轻：

- {{v:defaulted|announced}} **默认值（default）** 阶段：没有任何来源说明过阶段；
- {{v:unconfirmed|1,200 MW}} **待确认**的值：从文章中读出，但没有原句支持。

参见[数值从哪里来](provenance)。
