# 规则

系统里几乎所有信息都属于某一个园区：有文章点了它的名，页面上的每个数值都能追溯到一句关于它的原话。但有些新闻讲的是一个地方，而不是某个园区 —— 某个州暂停审批新的数据中心、某个镇禁止大型数据中心、电网运营机构针对大负荷新用户出台规定、全州范围的税收减免。**Rules**（规则）页面就是用来收录这类信息的，并告诉你每条规则波及哪些项目。

## 什么是规则

规则针对的是一个地方，或者同时针对所有园区，而不是某一个园区。它从新闻报道中读取，而且只有当文章自己的原句写明了规则内容、适用范围和当前进展时才会被收录；如果规则带有规模门槛之类的数字，这个数字也必须出现在原句里。文章撑不起来的规则会被直接舍弃，绝不会存一半真一半假的版本。多篇文章讲的是同一条规则时，算作一条，以最新的一篇为准来判断它现在走到哪一步 —— 因此，竞选承诺后来变成行政命令、命令又被法院叫停，读起来是同一条规则的前后经过。

每条规则都有：

| | 含义 |
| --- | --- |
| **Status**（状态） | *proposed*（已提出：提交议案、发起请愿或付诸表决）、*pledged*（已承诺：官员或候选人公开表态要做）、*passed*（已通过，尚未生效）、*in force*（已生效）、*blocked*（被法院暂时叫停，日后仍可能恢复效力）、*lifted*（已废止或到期）、*voted down*（被否决）。 |
| **Effect**（作用） | *restricts*（限制）—— 让建设更难：禁令、暂停令、暂停审批、新增成本。*eases*（放宽）—— 让建设更容易：免税、按规划直接准建、允许大负荷用户自建电源的法律。 |
| **Need**（涉及需求） | 它影响园区哪方面的需求，用词和障碍相同：审批、电网容量、用水、设备供应…… |
| **Covers**（适用对象） | 适用于哪些项目：尚未拿到许可的、尚未投运的，或所有未取消的项目；如果规则规定了规模门槛，则只限门槛以上的项目。 |

## 规则波及哪些项目

匹配由代码里写定的规则完成，从不交给模型判断；每一条匹配都会用一句话说明理由，例如 *TX · announced · no permit on record*（得州 · 已宣布 · 无许可记录）。

| 规则针对 | 按项目的什么来匹配 | 匹配程度 |
| --- | --- | --- |
| 一个州 | 项目所在的州 | exact（确定） |
| 一个县 | 所在州和县 | exact（确定） |
| 一个镇 | 所在州，以及项目登记所在的镇 | likely（可能） |
| 某个电网运营机构的辖区 | 所在州 —— 前提是该州大部分处在这个辖区内 | likely（可能） |
| 全国，或某一种投入品 | 不匹配任何项目 | —— |

接着看阶段：针对"尚未拿到许可"的规则，只波及处于已宣布或审批阶段、且没有任何获批许可记录的项目；针对"尚未投运"的规则，不包括已经投运的项目。规模小于门槛的项目不计入；没人公布过规模的项目则保留，记为 *likely*。已废止或被否决的规则不波及任何项目。

### 确定与可能

**exact**（确定）表示园区就登记在规则点名的州或县，而且处在规则覆盖的阶段。**likely**（可能）表示匹配中有一部分是推断出来的，理由里会写明是哪一部分：

- **没有核对镇的边界。** 系统中没有任何项目有真实的场址坐标：地图上的点是它登记所在城镇的中心。园区究竟在不在这个镇的辖区之内，无法核实，所以镇一级的规则只能把登记在该镇名下的项目标为 *likely*。如果一个园区登记的是邮寄地址所在的城市、实际却坐落在相邻的乡镇，在拿到真实场址之前就会被误配。
- **电网辖区是根据州推断的。** 只有全部或大部分处在同一电网运营机构辖区内的州才参与匹配 —— 得州对应 ERCOT，弗吉尼亚和俄亥俄对应 PJM，以此类推。横跨多个运营机构的州，例如伊利诺伊、印第安纳、密歇根、肯塔基、密苏里，不匹配任何电网运营机构的规则。已知的例外：得州不在 ERCOT 范围内的地区（埃尔帕索、狭长地带、东北角），以及加州不在 CAISO 范围内的地区。
- **规模未知。** 规则设了门槛，但没人公布过这个园区的规模。

## 规则不是障碍

规则波及某个园区，这件事与园区自身的障碍分开记录。它不算进障碍数，不会被选为最大障碍，不影响园区的可信度和完整度，也绝不会让项目在 [Monitor](monitor)（关注）页面上显示为 *blocked*（受阻）。项目页面上的其他内容都能追溯到关于这个园区的文章；规则之所以波及它，只是因为它所在的地方。把两者分开，才能让前面这句话一直成立。

## 面向全行业的规则不标记任何项目

对变压器加征关税、芯片出口管制、战争对供应链的冲击 —— 这些同时影响每一个园区。把所有项目都标上，等于什么也没说，你也无从据此采取行动。所以这类规则列在页面底部的 **Market**（市场）一栏，不波及任何项目。某个园区只有在关于它的文章提到时才会体现这类影响 —— 比如"变压器交付推迟到 2028 年"，就是这个园区自己的障碍，附有它自己的原句。

## 页面说明

- **统计块** —— 当前显示多少条规则、其中限制和放宽各有多少，限制性规则波及多少个项目，已生效的限制有多少，以及市场类规则有多少。
- **state**（州）—— 只看某个州的规则。选中一个州时，也会带上该州大部分所处的电网辖区的规则，所以选得州会看到 ERCOT 的规则。
- **Include lifted and voted down**（包括已废止和被否决的）—— 加上已经失效的规则。它们不波及任何项目，仅作为历史记录。
- **每条规则一张卡片** —— 适用地点、规则类型和涉及的需求；状态和作用；一句话摘要；适用对象、相关日期、首次和最近一次报道的时间；如果是限制性规则，还会写明什么情况能让它解除。
- **the N projects it reaches**（波及的 N 个项目）展开项目列表：每个项目（链接到[项目详情页](project-page)）、所属公司、地点和阶段、匹配程度，以及匹配理由。确定的匹配排在前面。
- **the N articles**（N 篇文章）展开这条规则背后的文章，最新的在前：标题（点击打开原文）、发布方、日期、这篇文章当时报道的状态，以及规则所依据的每一句原话，并标明这句话证实了什么 —— *the rule*（规则本身）、*where*（适用地点）、*where it stands*（当前进展）、*the size threshold*（规模门槛）。一句话同时证实几件事时只显示一次。

## 规则还会出现在哪里

- 在[项目详情页](project-page)上，**Exposed to**（受其限制）列出限制该园区所在地的规则，**Helped by**（受其利好）列出放宽的规则。
- 在 [Monitor](monitor)（关注）页面上，**Rules for their places**（所在地的规则）把波及你所关注项目的每条规则各列一次，附上它波及的项目；如果是限制性规则，还会写明什么情况能让它解除。
