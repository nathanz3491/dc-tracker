# 数据来源

dc-tracker 中的一切都来自公开来源。没有任何数据是购买、泄露或私下获得的；也没有任何数字是把追踪系统自己的估算当作报道值来呈现：凡是追踪系统自行算出的值，都会标注为[推导（derived）或推断（inferred）](provenance)。

## 来源

| 来源 | 提供什么 | 权重 |
| --- | --- | --- |
| **公司文件与公告**——运营商新闻室、新闻稿、SEC 文件 | 关于规划、容量、投资和里程碑的第一手陈述 | 3 |
| **政府文件**——许可证、分区与规划记录、经济发展公告 | 审批、申报、官方数字 | 3 |
| **行业媒体**——数据中心及相关行业出版物 | 详细报道，往往最先刊出 | 2 |
| **综合媒体**——全国性和地方新闻 | 地方反应、反对意见、许可证、公用事业新闻 | 1 |
| **电网接入排队名单** | 申请接入的大型负荷；仅靠关键词与园区匹配，因此是较弱的证据 | 1 |
| **目录网站、维基和资讯汇编**——设施目录、项目追踪网站、百科 | 只用于补缺（见下文） | — |
| **美国人口普查参考数据** | 某地的县中心和镇中心坐标 | 仅作参考 |

权重表示一个来源在[可信度](confidence)计算中、以及在来源之间出现分歧时所占的分量。权重按来源类型人工设定，而不是按发布方设定。

### 目录网站和维基只用于补缺

设施目录、项目追踪网站和维基很有用，但属于二手信息：它们常常没有日期，而且常常把单栋楼的数字和整个园区的数字混在一起。因此它们会作为引用保留，但**只填补没有任何第一手来源说明的字段**，绝不取代第一手来源，也绝不算作佐证。

### 屏蔽自动读取的发布方

有些发布方拒绝一切自动访问者。追踪系统不会设法绕过。尤其是其中两家——DatacenterDynamics 和 Data Center Frontier——追踪系统通过一个新闻搜索服务获知它们的标题，再从其他媒体或运营商自己的新闻稿中读到同一条消息。它们本身的网页从不被抓取。

## 如何发现文章

- 选定发布方和运营商新闻室的**新闻订阅源和站点地图**，每天检查。
- 针对地点和事件进行**网页搜索**——例如某个县名加“data center”、一次许可证表决——以找到订阅源遗漏的报道。
- 云计算公司、数据中心房东和公用事业公司的 **SEC 文件**。
- 追踪系统补缺时，针对某个园区缺失信息进行的**定向搜索**。

新文章进入一个队列，最近的新闻优先读取。

## 如何读取和核查一个数字

1. **读取。** 一个语言模型阅读文章，提取其中描述的每一个园区：谁、在哪里、多大、多少钱、什么时候、处于什么阶段、面临什么障碍，以及每个数值背后的原句。
2. **原句核查。** 只有当一个数值的原句确实出现在文章中、并且确实陈述了这个数值时，该数值才会作为*已引证（quoted）*保留。参见[数值从哪里来](provenance)。
3. **规模核查。** 一个大到不可能属于单个场地的数字——比如每兆瓦超过 5,000 万美元（$50 million）——会被暂扣，标为 *not this site's figure*（不属于本场地的数字）。单栋楼的数字不计入园区总数。预期（尚未发生）的事件与已达成的里程碑分开保存。
4. **匹配。** 园区会与已有的某一行记录匹配；如果是新园区，在新建记录之前会先与相似的记录比对。参见[重复项目](duplicates)。
5. **合并计算。** 园区的各个字段根据其全部来源重新计算。参见[字段说明](fields)。
6. **交叉核查。** 规则会查找矛盾之处——运行容量超过规划容量、某个日期早于园区宣布日期、每兆瓦成本不合常理。当两个已引证的数字相互矛盾时，模型可以在已发布的数字之间做出选择，也可以拒绝选择；它永远不能自行填入一个新数值，而落选的数字会被保留，并标记为已搁置。

## 抓取程序如何运作

追踪系统会向它访问的每个网站表明自己的身份，先查询并遵守每个网站的 `robots.txt`，对同一网站的请求之间会等待，遇到错误时会放慢速度。它不会伪装成浏览器来绕过屏蔽。它会保留一份文章文本的私有副本，以便重新阅读和核查；它不会转载文章。发布方可以要求它放慢速度或停止。

## 不使用什么

- 不猜测任何数字。追踪系统找不到来源的估算值不会作为数值存储。
- 不使用私有或付费数据。
- 不用任何内容训练任何模型。
