# 项目

**Projects**（项目）页面列出系统所知的每一个园区，每个园区一行，每个数值都标明出处。

## 搜索

在 **name, city, operator…**（名称、城市、运营商……）中输入。每个词都必须出现在该行的某处：编号、名称、公司、租户、城市、县、州或最大障碍。公司既可以按表格显示的名称找到，也可以按来源使用的写法找到，所以输入 `amazon` 能找到以 "AWS" 归档的园区。要直接跳到某个园区，输入井号加编号，例如 `#42`。

## 筛选

**Filters**（筛选）会打开筛选面板；按钮上显示已设置的筛选条件数量，**Clear**（清除）会把它们全部移除。

| 筛选条件 | 保留什么 |
| --- | --- |
| **state**（州） | 某一个州的园区。 |
| **phase**（阶段） | 某一个阶段：已宣布、审批中、在建、运营中、暂停或已取消。参见[阶段与进展](progress)。 |
| **confidence**（可信度） | *1 or better*（1 及以上）、*2 or better*（2 及以上）或 *3 only*（仅 3）。参见[可信度](confidence)。 |
| **obstacle**（障碍） | 有某一类未解决障碍的园区，例如 `grid_capacity` 或 `community_opposition`。 |
| **severity**（严重程度） | 有至少达到该严重程度的未解决障碍的园区：关注、重大、阻断。 |
| **Quoted only**（仅已引证） | 每个已填写字段都是已引证或查得的行 —— 没有任何字段是待确认、推断或默认值。 |
| **Suspected delays only**（仅疑似延期） | 自己的预计上线日期已过、却没有任何信息表明已在运行的园区。开关上会显示共有多少个。参见[数字与日期](numbers-and-dates)。 |

障碍筛选和严重程度筛选是分开检查的：只要一行有*某个*该类型的未解决障碍，并且有*某个*该严重程度的未解决障碍，它就能通过，而这两个障碍不必是同一个。

## 列

表格总是以 **#** 开头 —— 园区编号，旁边是它的 ☆ 关注按钮 —— 后面是各个跟踪字段。默认显示哪些字段取决于它们的填充程度：至少一半园区都已填写的字段会显示，其余的收在 **Show N sparser fields**（显示 N 个较稀疏的字段）后面。所以随着数据增长，默认列可能会变化。

| 列 | 含义 |
| --- | --- |
| **Project**（项目） | 园区名称。 |
| **Operator**（运营商） | 建设并运营它的公司。 |
| **Buyer**（买方） | 将使用它的租户（如果有来源点名）。 |
| **City**（城市）、**State**（州） | 所在位置。 |
| **Phase**（阶段） | 它进展到哪一步。 |
| **Late**（逾期） | 对疑似延期的园区，以琥珀色显示其预计上线日期所指时段结束了多少天；鼠标悬停可看到原因。其他园区留空。总是显示，紧挨着 Phase 列。 |
| **Planned (MW)**（规划容量，MW） | 规划容量，单位为兆瓦。 |
| **Running (MW)**（运行容量，MW） | 目前已通电的容量。 |
| **Investment (USD)**（投资，美元） | 已宣布的投资。 |
| **Announced**（宣布时间） | 首次宣布的时间。 |
| **Online**（投运时间） | 预计投入运行的时间。 |
| **Biggest obstacle**（最大障碍） | 最严重的未解决障碍，用一句话描述。 |

**Operator**（运营商）和 **Buyer**（买方）列中的每家公司都只用一个名称显示，不论园区的来源怎样写：AWS、Amazon Web Services 和 Amazon Data Services 都显示为 *Amazon*，RagingWire 显示为 *NTT*。这个名称取自追踪器的运营商名单，不在名单上的则用大多数园区使用的写法；控制台的每个页面都用同一个名称。两者不同时，园区自己的页面会在名称旁显示来源的写法。没有点名的租户（例如 "a Fortune 100 company"）按原文显示。

开启 **All fields**（全部字段）后，你还会看到 **Compute (H200-eq)**（算力，H200 等效）、**County**（县）、**Lat**（纬度）、**Lon**（经度）、**Confidence (0-3)**（可信度，0-3）和 **Verified**（已核实）。每个字段的定义都在[字段说明](fields)中。

末尾有两列是汇总信息，不能排序：

- **filled**（已填写）—— 十二个跟踪字段中填写了多少个：9 个及以上为绿色，少于 6 个为琥珀色。
- **tracks**（进展轨道）—— 五个小格子，每条进展轨道一个。深色：已达成。浅色：仅由后续里程碑推定。红色：受阻。灰色：尚未达成。参见[阶段与进展](progress)。

## 读懂一个数值

每个数值都以某种样式显示，样式说明了它的出处；把鼠标悬停在上面（手机上则是点按）即可看到它背后的原句。表格上方的 **what do the underlines mean?**（下划线是什么意思？）会打开图例。简而言之：

| 看起来像 | 含义 |
| --- | --- |
| {{v:reported|1,200 MW}} | 已引证（quoted）：有来源这样说，而且我们核对过原句。 |
| {{v:derived|Loudoun County}} | 推导（derived）：查得或计算得出，而非报道所得。 |
| {{v:unconfirmed|1,200 MW}} | 待确认：已提取，但还没有原句佐证。 |
| {{v:inferred|电网容量}} | 推断（inferred）：模型的判断。 |
| {{v:defaulted|announced}} | 默认值（default）：没有人说过；这是兜底值。 |
| {{v:missing|—}} | 空。 |

[数值从哪里来](provenance)逐一解释了这些标签。数字上的小标记也很重要：

- **~** 表示约数，**≤** 表示最多，数字后的 **+** 表示至少；
- **◒** 表示该数字是整个场址的用电功率，而不是其计算负载；**⚡** 表示它是发电机的额定功率。两者都不能与无标记的数字直接比较。参见[数字与日期](numbers-and-dates)；
- 日期只按来源给出的精度显示："2027" 表示来源说的是 2027 年，而不是 1 月 1 日。

表格上方的 **coverage**（覆盖率）显示填充最好和最差的各三个字段。

## 排序与加载

点击列标题即可按该列排序；第一次点击从高到低排序，再次点击则反转。空值总是排在最后。表格上方的状态行会说明有多少行符合条件，以及当前如何排序。按 **Late** 排序会把逾期最久的园区排在最前；同时开启 **Suspected delays only**，就会按逾期从久到短列出全部疑似延期的园区。

默认按可信度从高到低排序 —— 尽管可信度列只有在开启 **All fields** 后才会显示。

滚动时每次加载三十行；**Load N more**（再加载 N 行）可以用键盘完成同样的操作。

## 打开一个园区

点击一行，或用 Tab 键移到该行后按 Enter，即可打开[它的页面](project-page)。把鼠标悬停在 **#** 编号上，会显示该园区的内部识别键，正是它决定了两行是否属于同一个园区。

在窄屏上，表格会变成卡片：名称、可信度、地点和阶段（疑似延期的园区会附上 *late N days*，即逾期 N 天）、规划兆瓦数和投资、已填写多少字段，以及进展轨道。

## 没有匹配结果时

*No project matches these filters*（没有项目符合这些筛选条件）—— 放宽可信度下限、清除障碍筛选，或清除搜索内容。
